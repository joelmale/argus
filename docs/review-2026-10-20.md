## P1 — security

| # | Problem | Fix |
|---|---|---|
| 5 | **Password-reset tokens are accepted as login tokens.** `decode_token` (`app/core/security.py`) accepts any JWT signed with the app key, so a reset link's token works as a 30-minute bearer token. Introduced with email reset; not exploitable on HomePod today because SMTP is off and no reset tokens are issued. | `decode_token` must reject tokens carrying a `purpose` claim (or require an explicit access-token type). **fixed on branch** `fix/proxy-findings-tokens`. |
| 6 | **Rate limiting keyed on the proxy's address.** All browser traffic reaches the backend from the frontend container, so `10/minute` on login was one shared bucket: one person mistyping a password locked everyone out. Trusting `X-Forwarded-For` isn't an option: Next.js forwards a client-supplied value untouched, so it can be spoofed. | Failed logins are now limited **per account** (10 per 5 minutes, reset on success); reset emails per account (3 per 15 minutes); the per-address limits are loosened to flood protection (60/30 per minute). **fixed on branch** `fix/security-pass`. |
| 7 | **`APP_SECRET_KEY` contains `$`**, which Compose treats as variable interpolation, so containers use a shortened key. Rotating or re-storing it will log everyone out. | Escape `$` as `$$` or use a key without `$`, then move it to a Dockhand secret. **open (ops)** |
| 8 | **Secrets stored as plain stack values in Dockhand**: DB password, app secret key, SNMPv3 keys (Argus); `INSOC_API_TOKEN` (InSOC). | Mark them secret in Dockhand; do it together with #7. **open (ops)** |
| 9 | **Session handling**: the JWT lived in `localStorage` (readable by any injected script), and changing a password didn't invalidate existing tokens. | Login now sets an `HttpOnly`, `SameSite=Strict` session cookie (the browser keeps only a non-secret "signed in" marker; the WebSocket authenticates with the cookie). Tokens carry a per-user version: password reset (web or CLI), deactivation and the new `POST /auth/sessions/revoke` ("sign out everywhere") invalidate every earlier token. `POST /auth/logout` clears the cookie. Migration `20261020_0040` adds `users.token_version`. **fixed on branch** `fix/security-pass`. |
| 10 | `/docs` and `/openapi.json` are public on port 8000. | Acceptable on a LAN; disable in production or require auth if the port is ever exposed. **open (low)** |

## Ops steps for #7 and #8 (Dockhand UI)

These change stack settings, so they're yours to make. Do them in one sitting, then redeploy each stack once.

**Argus stack → Environment**
1. Replace `APP_SECRET_KEY` with a new value **without `$`**, e.g. the output of `openssl rand -hex 32`, and mark it **secret**. This signs everyone out once.
2. Mark `POSTGRES_PASSWORD`, `DATABASE_URL_DOCKER`, `SCANNER_DATABASE_URL`, `SNMP_V3_AUTH_KEY` and `SNMP_V3_PRIV_KEY` as **secret**, keeping their values. Don't change the DB password value here: Postgres only reads it when the volume is first created.
3. Optionally delete `SMTP_USERNAME` (`alerts@example.com`, unused while SMTP is off).

**InSOC stack → Environment**
4. Mark `INSOC_API_TOKEN` **secret**.

Why secret fixes the `$` problem: Dockhand writes plain values into an env file that Compose interpolates (`$h…` disappears), while secrets are passed as shell environment, which Compose doesn't re-expand. A hex key avoids the issue either way.
