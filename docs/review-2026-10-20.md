## P0 — broken in production now

| # | Problem | Evidence | Fix |
|---|---|---|---|
| 1 | **Assets and Scans lists don't load in the browser.** Next.js strips the trailing slash (`/api/v1/scans/` → 308 `/api/v1/scans`), FastAPI adds it back with a redirect to the *internal* host (307 `http://backend:8000/api/v1/scans/`), which the browser can't reach. | Backend log: every `GET /api/v1/scans` and `GET /api/v1/assets?...` is a 307 with no follow-up request. `curl :3008/api/v1/scans/` → 308, then 307 to `backend:8000`. | `skipTrailingSlashRedirect: true` in Next, and the backend answers list routes with or without the slash. **fixed on branch** `fix/proxy-findings-tokens`. |
| 2 | **Scans blocked after any scanner restart.** A job left `running` by a dead worker blocks every scheduled and manual scan forever. | Scanner log: `Scheduled scan skipped: existing scheduled job is still active (job_id=859254f7…)` every minute; the manual scan never started. | Fail orphaned jobs on worker start, plus a staleness guard. **fixed on branch** `fix/stale-scan-jobs` (`cbe6b27`). |
| 3 | **Live updates never connect.** The browser opens `ws://<frontend>:3008/ws/events`, but Next only proxies `/api/*`; `/ws/*` 404s. `NEXT_PUBLIC_WS_URL` is baked in at image build time, so setting it in the stack does nothing. | Browser console: `WebSocket connection to 'ws://192.168.100.20:3008/ws/events' failed`. | Add a `/ws/:path*` rewrite and confirm Next proxies the upgrade; verified with a production build. **fixed on branch** `fix/proxy-findings-tokens`. |
| 4 | **Asset detail “Findings” section always fails.** The frontend calls `GET /api/v1/assets/{id}/findings`, which doesn't exist. | `frontend/src/lib/api.ts:156`; no matching backend route. | Call `GET /api/v1/findings/?asset_id={id}`. **fixed on branch** `fix/proxy-findings-tokens`. |

## P1 — security

| # | Problem | Fix |
|---|---|---|
| 5 | **Password-reset tokens are accepted as login tokens.** `decode_token` (`app/core/security.py`) accepts any JWT signed with the app key, so a reset link's token works as a 30-minute bearer token. Introduced with email reset; not exploitable on HomePod today because SMTP is off and no reset tokens are issued. | `decode_token` must reject tokens carrying a `purpose` claim (or require an explicit access-token type). **fixed on branch** `fix/proxy-findings-tokens`. |
| 6 | **Rate limiting keys on the proxy's address.** All browser traffic reaches the backend from the frontend container, so `10/minute` on login is one shared bucket: one person mistyping a password locks everyone out, and the limit doesn't slow a real attacker going through the UI. | Run uvicorn with `--proxy-headers --forwarded-allow-ips=<frontend>` and key the limiter on the forwarded client address. **open** |
| 7 | **`APP_SECRET_KEY` contains `$`**, which Compose treats as variable interpolation, so containers use a shortened key. Rotating or re-storing it will log everyone out. | Escape `$` as `$$` or use a key without `$`, then move it to a Dockhand secret. **open (ops)** |
| 8 | **Secrets stored as plain stack values in Dockhand**: DB password, app secret key, SNMPv3 keys (Argus); `INSOC_API_TOKEN` (InSOC). | Mark them secret in Dockhand; do it together with #7. **open (ops)** |
| 9 | **Session handling**: the JWT lives in `localStorage` (readable by any injected script), and changing a password doesn't invalidate existing tokens (24h default, 4 days with “remember me”). | Backlog item 1.6 (httpOnly cookie) plus a per-user token version checked in `get_current_user`. **open** |
| 10 | `/docs` and `/openapi.json` are public on port 8000. | Acceptable on a LAN; disable in production or require auth if the port is ever exposed. **open (low)** |
